# Acceptance criteria and verification matrix

Specification date: 2026-10-08. All application criteria below are **not yet executed**. Passing documentation review does not mean the application meets them. Prompt 2 must record pass/fail/not-run and evidence in a release report. Required baseline is authored-only plus links-only terminology.

## Functional gates

- **AC-01 / F01 / M3:** landing renders project purpose, two working primary navigation actions, educational notice and version-policy link. Browser test follows each action; no fabricated claims remain in content review.
- **AC-02 / F02 / M4:** all eight specified articles exist with objectives, prerequisites, illustration, pitfall, related links, sources and review dates. Content checker validates fields; editorial review confirms substantive original explanations, not placeholders.
- **AC-03 / F03 / M6:** exactly six domain pages and index records; class/text filters combine correctly, Clear resets, back/forward restores state. Test `class=findings` returns LB/VS, then q=LB returns only LB. Every page shows scope and context.
- **AC-04 / F04 / M5–6:** exactly 44 unique profile/domain/variable records match the manifest (7+8+7+6+8+8). Every link resolves to its domain-context detail page. Test USUBJID separately in DM and AE; no route collision. Explicit unavailable official metadata state is visible.
- **AC-05 / F04 / M5:** authored example types never render as SDTM types. In baseline mode all `officialMetadata` values are null. Negative test: insert an unsourced official core value and the validator fails. Unknown metadata is never presented as Permissible.
- **AC-06 / F05 / M7:** search handles blank/whitespace, punctuation, mixed case, malformed encoded hash, no match, cleared filters, index failure and keyboard operation. Exact `AESEQ` returns its page first; `USUBJID` returns all six context-specific pages before nonexact results; kind/domain filters narrow deterministically. No query appears in network requests or storage. 120-character cap is enforced. Reload and back/forward restore hash state.
- **AC-07A / F06 / M5–6, required:** links-only terminology page contains an original explanation, official publisher/release links, and no fabricated term records, codelist IDs or variable bindings. It has no empty “coming soon” browser.
- **AC-07B / F06 / M5, optional:** if approved-subset mode is chosen, both complete NY/SEX lists are resolved from the exact dated source; actual IDs, notices, digest, header version and membership checks pass. Attribution visible on pages/downloads; index uses only approved records. Missing/mismatched evidence rejects import. If not implemented, record “not applicable—links-only profile”; do not fail baseline V1.
- **AC-08 / F07 / M8:** three original synthetic walkthroughs, 2/4/2 output rows respectively, JSON/CSV/manifest parity, stable identifiers and trace links, ≥3 limitations each. No date precision imputation, formula-leading cells, real patient data or copied external fixtures. Download content matches previews and declared columns. Demonstration tokens are not labeled verified CT without evidence.
- **AC-09 / F08 / M4–9:** 24 specified authored glossary entries; resources, standards/versions, sources, about and privacy pages exist. Every profile shows model, IG and content version independently; CT appears only when bundled. All internal links and stable anchors resolve; unknown versions/records return 404.

## Cross-cutting gates

- **AC-10 / M3–9 / accessibility:** axe-based checks have zero serious/critical violations on home, article, domain index, variable, terminology, example and search templates. Manual keyboard review covers skip link, menu, filters, results, reading-mode/wrap controls, copy and downloads; focus remains visible and returns correctly. Record screen-reader smoke testing of headings, table/record mode and search status. Apply the AC-17 viewport matrix plus 200% text zoom/400% browser zoom. No page-level horizontal overflow; tables/code may scroll locally. Contrast meets the WCAG 2.2 AA target; primary touch controls meet the design's 44×44 CSS px requirement. Do not equate axe success with complete conformance.
- **AC-11 / M9 / SEO:** substantive article/domain/variable content exists in exported HTML without JavaScript. Titles/descriptions unique; sitemap contains canonical public content routes only; search and preview pages noindex; no placeholder production origin. With JS disabled, links and reading work and search supplies browse alternatives.
- **AC-12 / M7–10 / performance:** index ≤150 KB gzip and initial route JS ≤200 KB gzip. Run production export locally, not dev mode; record browser/tool/device versions. Warm search p95 ≤100 ms over 100 representative queries on the recorded CI runner. Proposed Lighthouse mobile targets: performance ≥90, accessibility ≥95, SEO ≥95 on home/article/domain using median of three runs. Record LCP ≤2.5s and CLS ≤0.1 under the chosen lab profile as lab targets, not observed field metrics. If budgets fail, fix or document an explicit scope/architecture decision; do not quietly claim compliance.
- **AC-13 / M5–10 / provenance:** 100% published reference/CT records resolve to source and permission evidence; all original content identifies authorship and source references for external claims. Negative fixtures reject uncertain bundle permission, duplicate identities, mismatched releases, missing source IDs and dangling codelist memberships. Generated search/downloads cannot bypass the gate.
- **AC-14 / M10–11 / security:** no uploads, tracking or external runtime dependencies; escaping test displays `<script>` as text; no eval/raw HTML injection. Header config is validated against final output and tested with a header-aware local server. CSP hashes match emitted inline scripts, search loads successfully, frame restrictions and MIME headers hold. Verify live host headers only after deployment authorization; mark that part pending until then. No untriaged high/critical dependency issue, unresolved dependency distribution license, or detected secret in release output.
- **AC-15 / M10–11 / operations:** clean installation using lockfile on pinned runtime passes release command; build requires no external standards service or secret; valid 404s and sample downloads survive static hosting. Record artifact manifest and reproduce content/search/example artifacts from the same inputs. Document host-specific config, rollback and unresolved launch gates. Do not deploy to prove a local criterion.

## AC-16 — Independent visual identity / M3–9

Release requires an original ClinDevLab identity reflecting clinical science, structured data and software engineering. Inspect its landing, domain detail, variable detail and synthetic-example screens. Record an explicit design review against DESIGN-SYSTEM: editorial serif headings, original warm-neutral/teal palette, annotated data exhibits and task-specific page compositions; absence of decorative blueprint grids, hospital-dashboard motifs and an unchanged generic documentation theme. Color adjustments to meet contrast are allowed if documented and independently selected.

The asset/component inventory must show no Blueprint-derived branding, layouts, typography system, colors, components or animations. Inspect this project's own assets, dependencies and design rationale only; do not access Blueprint's repository/infrastructure or create a comparative screenshot dependency. A text search alone cannot establish visual independence. Record the actual reviewer and evidence; do not invent owner approval or claim a comparison was performed. Playwright snapshots can detect subsequent regressions but do not prove originality. Failure of this review blocks visual completion.

## AC-17 — Responsive usability / F03–F08 / M3–10

The following is the authoritative future Playwright coverage, in CSS pixels. It is planned coverage, not executed testing:

- Chromium complete responsive suite: phone portrait 360×800 and 390×844; phone landscape 844×390; tablet/iPad-size portrait 768×1024 and 820×1180; tablet landscape 1024×768 and 1180×820; laptop 1366×768; large desktop 1920×1080 and 2560×1440.
- WebKit responsive smoke suite with touch-capable phone/tablet contexts where supported: 390×844, 820×1180 and 1180×820. Firefox smoke suite: 1366×768 and 1920×1080. Use compatible Playwright project settings and record the pinned browser versions; these are emulated contexts, not proof of physical iPhone/iPad behavior.
- Chromium additional reflow checks at 320×800, plus breakpoint edges 767/768, 1199/1200 and 1599/1600px wide at 900px high. Exercise a live portrait-to-landscape resize with an active search and an open menu. Do not treat viewport shrinking as a substitute for the manual zoom tests in AC-10.

Complete-suite pages: home, one article, domain index, VS detail/variable table, VSDTC detail, terminology, search, and all three synthetic examples. Smoke-suite pages: VS detail, VSDTC detail, search and vital-signs example, plus the shared navigation. At each required size:

1. Assert document scroll width is at most viewport client width +1px; inspect intentional local overflow separately. No overlays obscure focused controls, source notices or actions. Scrollable table/code regions expose their last column/line to keyboard and touch/pointer interaction.
2. Assert the variable table exposes every expected column and row. Switch to Read as records and compare every field label/value against the same approved fixture. Repeat for all synthetic datasets in the full suite. Null indications, complete identifiers, context and provenance remain readable; no mobile-only filtering or truncation.
3. Read full metadata/source URLs and version labels. Verify long-content fixtures wrap without page overflow. These are UI test fixtures, not additional published clinical metadata.
4. Search `USUBJID`, select a domain/kind filter, open a result, return and clear. Check controls, active state and count remain usable, and resize/reload preserves URL state. Open/close navigation with keyboard and touch-capable input, verify all destinations, Escape/focus return and short-landscape access.
5. Toggle code wrapping and confirm copied text/download bytes stay identical. Reach download/copy controls without horizontal page movement. Check success/error announcements and stacked input/output reading order.
6. Capture representative screenshots for home, VS detail, VSDTC detail, search with filters and the vital-signs example. Review layout and clipping; approve originals explicitly before using snapshots as regression baselines. Keep failure traces and record tested viewport/engine in the implementation report.

Manual supplement: check touch scrolling and on-screen-keyboard obstruction on a physical phone/tablet when available, and perform actual zoom and screen-reader checks. If hardware is unavailable, report physical-device behavior as unverified; do not report emulation as a device test. Required emulation/functional checks cannot be waived by screenshots. Responsiveness passes only when full information and task completion are preserved, not merely when the page fits the viewport.

## Completion levels

**Implementation complete locally:** AC-01–06, 07A, 08–17 pass for local scope, with optional 07B marked as applicable or excluded. Manual checks actually performed must have evidence; missing manual checks remain explicit release gates. A local implementation may be delivered with documented verification limitations but may not be called fully release-verified.

**Publishable:** local gate plus owner authorization, repository identity verification, outbound project license decision, actual domain/provider eligibility, live header/HTTPS/canonical checks, and reviewed educational content. Production-only checks cannot be marked passed from config inspection.
